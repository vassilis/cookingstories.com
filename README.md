# Cooking Stories

Cooking stories from all over the world: a recipe notebook where visitors can browse a shared collection and keep (or share) recipes of their own.

The site was a Jekyll page on GitHub Pages until 2026 (see the `gh-pages` branch). This branch is the Next.js rewrite.

## Stack

- Next.js 16 (App Router, Cache Components), English first with Greek at `/el`
- Postgres with Drizzle ORM
- Better Auth: email magic links (sent with Brevo), optional Google sign-in, admin role for reviewing public stories
- Cloudflare R2 for photos and database backups
- Self-hosted on a Hetzner server with Coolify, behind Cloudflare

## Local development

```bash
cp .env.example .env.local   # then fill in BETTER_AUTH_SECRET at least
docker compose up -d         # local Postgres on :5432
pnpm install
pnpm db:migrate
pnpm db:seed                 # loads the 44 house recipes in Greek and English
pnpm dev
```

Sign-in works without Brevo locally: the magic link is printed in the terminal running `pnpm dev`.

### Admin access

Put your email in `ADMIN_EMAILS` (in `.env.local`, or in Coolify for production) and sign in: that account becomes an admin and the header shows **Admin**, which leads to the recipe editor at `/admin`. For an account that already exists, run `pnpm admin:grant you@example.com`.

## Tests

Tests use two throwaway databases, which get emptied on every run. Create them once and set `TEST_DATABASE_URL` and `E2E_DATABASE_URL` in `.env.local` (see `.env.example`):

```bash
createdb cookingstories_test && createdb cookingstories_e2e
pnpm exec playwright install chromium   # once, for the browser tests
```

| Command | What it checks |
| --- | --- |
| `pnpm test:unit` | Pure logic: language routing (`proxy.ts`), the editor's text format, filters, form validation, the legacy converter |
| `pnpm test:db` | Against Postgres: only public, approved recipes ever reach public pages; admin edits save correctly |
| `pnpm test:e2e` | In Chromium against a production build on port 3100: home in both languages, filters, recipe pages, sign-in, the admin editor |
| `pnpm test` | Unit and database tests together |

GitHub Actions (`.github/workflows/ci.yml`) runs lint, types and all three suites on every push, and builds the Docker image.

## Project layout

| Path | What it is |
| --- | --- |
| `src/app/[lang]/` | Pages. `lang` is `en` or `el`; `src/proxy.ts` serves English without a prefix |
| `src/i18n/` | Locale config and the UI dictionaries (`en.json`, `el.json`) |
| `src/db/` | Drizzle schema. `auth-schema.ts` is generated by the Better Auth CLI |
| `src/lib/recipes.ts` | Data access for recipes (public recipes only, for now) |
| `src/lib/auth.ts` | Better Auth setup |
| `drizzle/` | SQL migrations (`pnpm db:generate` after changing the schema) |
| `data/legacy/recipes.json` | The original 2013 export |
| `data/seed/` | Seed data made from it (`pnpm legacy:convert`), plus `translations/en.json` |

Recipe text lives in `recipe_translations`, one row per language. A recipe has a `visibility` (`private`, `link` or `public`) and a `review_status`; listings only show public, approved recipes.

## Deploying with Coolify

1. In Coolify, add a **Postgres 17** resource and copy its internal connection URL.
2. Add the app from this GitHub repo with the **Dockerfile** build pack, port `3000`.
3. Set the environment variables from `.env.example`. `BETTER_AUTH_URL` is the public URL, e.g. `https://cookingstories.com`.
4. Deploy. The container applies pending migrations on start (`ops/scripts/migrate.mjs`).
5. Load the house recipes once, from the app's terminal in Coolify:
   ```bash
   node ops/scripts/seed.mjs
   ```
   Then restart the app (Coolify's **Restart**): pages cache recipe data in memory, so a page visited before seeding keeps showing the empty list until the cache is cleared.
   Admins come from `ADMIN_EMAILS`. To promote an existing account: `node ops/scripts/grant-admin.mjs you@example.com`.
6. Point the domain at the server through Cloudflare (proxied, SSL mode "Full (strict)").
7. In the Postgres resource, schedule backups to the R2 bucket (S3-compatible endpoint `https://<account-id>.r2.cloudflarestorage.com`).

### Email

Brevo sends the magic links through its HTTP API, so Hetzner's blocked SMTP ports don't matter. Add `cookingstories.com` as a sender domain in Brevo and publish its SPF, DKIM and DMARC records in Cloudflare DNS.

### Photos

Create an R2 bucket, attach the custom domain from `R2_PUBLIC_URL` (e.g. `images.cookingstories.com`), and create an API token with read and write access to that bucket. `src/lib/storage/r2.ts` hands the browser short-lived upload URLs; no page uses it yet.
